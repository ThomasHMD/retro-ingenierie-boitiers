# Préréglages V1 (patchs/v1.json = menu Pip-Boy + preglages-v1.json), outils/preglages_v1.py.
# La prise de vue n'est pas émulée : on joue la chaîne réelle du boîtier, fonction par fonction,
# sur une fiche de prise de vue posée en RAM libre (0x83F00000) :
#   FUN_0004793a(fiche + 0x2C)  recopie les réglages du menu dans la fiche (tâche 5)
#   FUN_0031a0f8(fiche, 0)      calcule les paramètres d'image (modes, matrice, courbe, secteurs)
#   FUN_0004b41c(fiche)         charge la puce ; c'est là qu'est le crochet (0x4B5B2 → 0x3F3000)
# (second crochet, 0x31B232 → preglage_reglages : netteté _DAT_83eb3d20, saturation _DAT_83eb3d44 et
# tons _DAT_83eb3d50 des 5 rendus, Moyennement élevée, Normale et Normal, posés juste après modesScene_reglages)
# puis on compare les registres de la puce (0x40010022 matrice, 0x40010034 YCbCr, 0x4001E400
# secteurs, 0x40018400/A400/C400 courbes) aux données de l'emplacement en ROM (préréglage V1) ou à
# ce que le code de Nikon a calculé dans la fiche (Nikon, Personnalisé, mode scène).
# Netteté, saturation, tons : la puce reçoit, pour chaque rendu, le paramètre de netteté (0x40010054),
# le demi-mot suivant (0x40010056, fixé par les tons) et la table de saturation (0x4001EC00) d'un
# Personnalisé réglé à la main sur Netteté Moyennement élevée, Tons Normal et Saturation Normale, dans le
# même mode couleur (références copiées en 0x83F08000). Teinte : elle ne change que la YCbCr (remplacée
# par le crochet) ; vérifié sur toute la page 0x40010000, et vaut 0° dans les 5 préréglages recyclés.
# python3 emulateur/d40emu.py scenario preglages-v1 --firmware build/v1/BD400111.BIN
